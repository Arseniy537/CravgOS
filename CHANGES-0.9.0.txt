CravgOS 0.9.0 - что изменилось (относительно 0.8.0)
===================================================

КОРОТКО
-------
1. Пиксельный режим: команда  wmboot  перезагружает систему в режим 1024x768 (VBE, 32 бита). Следующая загрузка снова обычная
   текстовая. В пиксельном режиме вся прежняя консоль (оболочка, gui, редактор) рисуется поверх пикселей.
2. cravgwm - плавающий оконный менеджер в стиле Openbox (команда  wm ). Ставится через stas одним пакетом:  stas install cravgwm
3. Программы-аналоги (каждая ставится отдельно, все настраиваются только XML-файлами в /etc/cravgwm/):
     cravgcomp (внутри cravgwm) - композитор, аналог picom: тени, прозрачность, скругление, плавное появление/исчезновение
     cravgbar   - панель, аналог tint2        cravgbg  - обои, аналог feh        cravgfm - файловый менеджер, аналог pcmanfm
     cravgrun   - лаунчер, аналог rofi        cravgterm - терминал               cwm-doc - справка по конфигурациям
4. Простой настройки нет, как вы просили: без файлов в /etc/cravgwm/ WM запускается "голым" (пустой фон, ни кнопок, ни меню, ни клавиш),
   работает только аварийный выход Ctrl+Alt+BackSpace. Всё включается и настраивается вашими XML-файлами.
5. Файловая система стала больше: 128 файлов по 8192 байта (было 64 по 2048). Старый диск переносится автоматически при первой загрузке.
6. Пакеты stas могут быть "связками" (--stas-bundle): много файлов за один запрос (cravgwm - 14 файлов, 54 КБ).
7. Lua: побитовые операторы  & | ~ << >>  (унарный ~ тоже), куча Lua 2,5 МиБ, расширение gfx.* и os.exec.
8. Версия 0.9.0.

КАК ПОЛЬЗОВАТЬСЯ (в виртуальной машине VirtualBox или QEMU с BIOS)
-----------------------------------------------------------------
    stas update
    stas install cravgwm cravgbar cravgbg cravgrun cravgterm cravgfm cwm-doc     (по одной команде на пакет)
    cwm-doc                      - справка: форматы всех XML-файлов (3 страницы)
    mkdir /etc ; mkdir /etc/cravgwm ; edit /etc/cravgwm/rc.xml      - написать настройки
    wmboot                       - перезагрузка в пиксельный режим (если чёрный экран - выключите машину: следующая загрузка обычная)
    wm                           - запуск оконного менеджера
    Ctrl+Alt+BackSpace           - выход из WM в консоль
    textboot                     - перезагрузка обратно в текстовый режим
    gfxinfo                      - показать режим, адрес видеобуфера, память
Переключение "графическая оболочка / wm": в пиксельном режиме команда  gui  запускает прежнюю текстовую оболочку (она рисуется
поверх пикселей), команда  wm  - оконный менеджер. Между текстовым и пиксельным режимом переключают wmboot / textboot (перезагрузка).

КЛЮЧЕВЫЕ ФАЙЛЫ НАСТРОЙКИ (минимальный пример смотрите в cwm-doc)
   /etc/cravgwm/rc.xml        рабочие столы, фокус, тема, клавиши, мышь, правила окон, автозапуск
   /etc/cravgwm/menu.xml      меню (как в Openbox); встроенные: client-list-menu, client-menu
   /etc/cravgwm/cravgcomp.xml, cravgbar.xml, cravgbg.xml, cravgrun.xml, cravgterm.xml, cravgfm.xml
   /etc/cravgwm/exec-allow    список программ (путь /apps/имя), которым разрешён os.exec; терминал выполняет команды оболочки только если
                              в этом файле есть строка /apps/cravgterm. Разрешены только неинтерактивные встроенные команды.
Файлы настройки - до 8192 байт; внутри можно подключать другие:  <include href="/etc/cravgwm/другой.xml"/>

НОВЫЕ ФАЙЛЫ
-----------
gfx.h, luagfx.h, fbcon.h   графический слой (поверхности, заливка, текст, смешивание, тени, градиенты, BMP), его функции для Lua,
                           консоль поверх пикселей и команды wm/wmboot/textboot/gfxinfo
wm/<имя>/*.lua             исходники пакетов WM (wm/cravgwm - 14 модулей, остальные - программы)
tools/stas_bundle.py       собирает wm/<имя>/ в stas-repo/<имя>.stp (связка stas)
stas-repo/cravgwm.stp, cravgbar.stp, cravgbg.stp, cravgfm.stp, cravgrun.stp, cravgterm.stp, cwm-doc.stp   готовые связки
tests/test_gfx.c, test_wm.c, gfx_env.h, test_vbe_asm.py, gen_testfont.py, shots2png.py   тесты (см. ниже)

ИЗМЕНЁННЫЕ ФАЙЛЫ
----------------
boot_iso.s   загрузчик BIOS: если в CMOS (регистр 0x7D) стоит одноразовый флаг 'W' (его ставит wmboot), флаг сбрасывается и включается
             линейный режим VBE 1024x768x32 (иначе 800x600, 640x480); информация о режиме и копия шрифта BIOS 8x16 передаются ядру.
             Обычная загрузка отличается только чтением этого флага.
boot.s       добавлены пустые символы fbinfo/romfont (сборка через GRUB работает без пиксельного режима)
kernel.c     файловая система 128x8192 (формат диска версии 2 + перенос версии 1), клавиша Super и физический код клавиши (kbase) для привязок,
             пиксельные координаты мыши, захват вывода команд (os.exec), команды wm, wmboot, textboot, gfxinfo, версия
fs.h         FS_MAXN 128, FS_FSZ 8192, обнуление данных при старте
lua.h        точка расширения (LUA_EXT), побитовые операторы, куча 2,5 МиБ
stas.h       пакеты-связки (--stas-bundle), заголовки --needs/--members, удаление связки целиком
tools/stas_mkrepo.py, Makefile (make repo теперь собирает и связки), tests/run_all.py (+ test_gfx, test_wm), HANDOFF-1.md, README.md

ПОВЕДЕНИЕ И ОГРАНИЧЕНИЯ (честно)
--------------------------------
* ВСЁ ПРОВЕРЕНО ТОЛЬКО НА ХОСТЕ: модульные тесты, эмуляция загрузчика, настоящий kernel.c с подложным железом, снимки экрана оконного менеджера
  (пиксели читаются из подложного видеобуфера). В VirtualBox/QEMU/на железе пиксельный режим и WM я НЕ запускал: у меня нет виртуальной машины.
* Код 16-битного загрузчика VBE проверен интерпретатором его ассемблерного текста (tests/test_vbe_asm.py: нормальный BIOS, нет 1024x768,
  нет подходящих режимов, отказы контроллера и установки режима), но не настоящим BIOS. Если после wmboot экран чёрный или система не загрузилась -
  выключите машину и включите снова: флаг одноразовый, следующая загрузка обычная.
* UEFI/GOP не поддерживается: загрузчик bootx64.efi из репозитория только выводит информацию и не запускает ядро. Пиксельный режим - только через BIOS (VBE).
* Нужен BIOS-VBE с линейным 32-битным режимом (VirtualBox и QEMU его дают) и не менее 40 МиБ ОЗУ.
* Образ диска меняет формат (версия 2). При первой загрузке 0.9.0 старый диск переносится автоматически; после этого прежние версии ядра
  этот диск не прочитают.
* Файловый менеджер изменяет файлы только в /lua (ограничение Lua-программ); смотреть можно везде. BMP-обои - до 8192 байт (маленькие картинки/узоры).
* Терминал не запускает интерактивные программы (редактор, игры, gui, setup...) и stas run.
* Шрифт только 8x16 (масштаб 1-4). Нет сглаживания, нет размытия под полупрозрачными окнами.
* Пакеты WM не встроены в ядро (они велики): для установки нужна сеть (stas update) или свой локальный сервер:  stas repo http://10.0.2.2:8000
* Мышь: колесо "вверх" - положительное значение; если у вас наоборот, задайте  <mouse wheel="inverted">  в rc.xml.
* Alt+Shift и Ctrl+Shift переключают раскладку RU/EN, как и раньше; привязки WM используют физические клавиши и от раскладки не зависят.

ТЕСТЫ

    python3 tests/test_vbe_asm.py                    загрузчик VBE на подложном BIOS
    python3 tests/host_lua.py && /tmp/host_lua       Lua в настоящем kernel.c;   python3 tests/host_stas.py && /tmp/host_stas

Результат на момент выпуска: все тесты проходят.
